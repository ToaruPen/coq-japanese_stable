# 複数行 UI テキストの名前変換除外

## 承認済みの目的

死亡サマリーなどの複数行テキストが、一般 UI sink でアイテム名全体として再解釈されることを防ぐ。2026-09-04 の調査結果に対するユーザーの修正依頼に基づく。

## 根拠と限界

`UITextSkinTranslationPatch.TranslatePreservingColors` は全文内の `with beamsplitter` 等を検出すると名前変換へ進む。名前変換には空白位置ごとの長い部分文字列の反復生成がある。約20万字の合成サマリーで約4.18 GBの累積割り当てを再現した。これはピーク使用メモリではない。

報告者の実際のサマリーは未取得であり、Windows Unity での死亡時停止と同一原因であることは未確認。今回の完了条件は、再現した過剰処理の経路制限であり、報告された停止全体の解消ではない。

## 変更する契約

- `TryTranslateDisplayNameWithClauseUiText` と `TryTranslateMixedDisplayNameSinkText` の入口で、可視テキストに CR または LF があれば名前変換を行わない。
- 共通 sink 全体を早期 return させない。既存の marker 除去、他の UI 変換、観測処理を維持する。
- 単一行の名前、色付き修飾句、relic 名、タブを含む能力値の変換を維持する。
- 描画、フォント、日誌 owner、保存データ、辞書、配布物は変更しない。

## 検証

L2 の既存 fixture を拡張し、LF / CRLF / CR、色付き with-clause、mixed sequence、marker、および単一行の正例を検証する。実装前の失敗と実装後の成功を確認する。既存の合成サマリー計測で割り当ての削減を再確認し、C# 全体テストと analyzer を含む build を実施する。

## 採用しない案

共通描画の変更やフォント再生成の削除は、今回の再現根拠とは別である。名前解析全体の書き換えより、誤った入力を渡している2分岐に限定する。全 UI の改行除外は合法な説明文まで抑制するため行わない。
