# Harmony 2.4.2 Distribution Design

## Goal

Ship QudJP 0.5.02 for Caves of Qud 1.0.5 and publish a separate, opt-in
Harmony 2.4.2 patch for players affected by slow Harmony patch application on
Windows or native Apple Silicon compatibility failures.

## Release Boundary

- QudJP 0.5.02 remains the normal Workshop and GitHub Release artifact.
- The QudJP mod ZIP must not contain or automatically replace `0Harmony.dll`.
- A separate `QudJP-Harmony-2.4.2-Windows.zip` asset provides the Windows
  updater, restorer, verified Harmony DLL, checksums, and license notices.
- Existing macOS opt-in install and restore commands remain in the QudJP mod
  ZIP. The Steam discussion links to the 0.5.02 release and explains both
  platform paths.

This keeps game-install mutation explicit and reversible while allowing one
GitHub Release to provide stable, checksum-addressable download links.

Existing files under local `dist/` are not release inputs. In particular, the
local 0.5.01 ZIP and its checksum do not match and must not be reused.

## Harmony Artifact

The build downloads the official `Harmony-Fat.2.4.2.0.zip` release asset and
accepts it only when its SHA-256 is
`a5fc5f9d9640b927d786a0527faa18bf7aa776788235140c59e9b73de87a7774`.
It extracts only `net48/0Harmony.dll` and accepts it only when its SHA-256 is
`77e6901ecc606aec66c2a972782a3779e4f50c037d2d165eb7ececdd4d8f794d`.

The generated Windows ZIP contains:

```text
QudJP-Harmony-2.4.2-Windows/
  Install Harmony 2.4.2.cmd
  Restore Game Harmony.cmd
  QudJP-Harmony-2.4.2.ps1
  README-ja.txt
  SHA256SUMS.txt
  LICENSE-QudJP.txt
  LICENSE-Harmony.txt
  THIRD-PARTY-NOTICES.txt
  payload/net48/0Harmony.dll
```

The release workflow creates the Windows ZIP and its sidecar checksum beside
the normal QudJP ZIP. Both are attached to the draft GitHub Release.

## Windows Update and Restore Contract

The command wrappers invoke the shared PowerShell implementation. The script:

1. Locates Caves of Qud through the Steam registry and library metadata, with a
   manual file picker fallback.
2. Accepts only a path ending in
   `Caves of Qud/CoQ_Data/Managed/0Harmony.dll`.
3. Refuses to continue while the `CoQ` process is running.
4. Requires an explicit `INSTALL` or `RESTORE` confirmation.
5. Never self-elevates from the user-writable extracted package. If the game
   directory is not writable, it fails closed and tells the user to close the
   window and use Explorer's `Run as administrator` on the fixed install or
   restore CMD wrapper.
6. Verifies the bundled 2.4.2 DLL before touching the game installation.
7. Accepts the known Caves of Qud 1.0.5 Harmony 2.2.2 DLL as the install
   source. Unknown game DLL hashes fail closed.
8. Holds a cross-session exclusive lock file in the target `Managed` directory
   across revalidation, backup, replacement, and rollback. Lock acquisition
   retries for at most 30 seconds with `FileShare.None`; releasing the handle
   leaves the lock file in place to avoid an unlink race.
9. Copies the original to a unique sibling temporary file through exclusive
   streams, closes and verifies that file, then publishes it to
   `0Harmony.dll.qudjp-backup-before-2.4.2` with no-overwrite `File.Move`. If a
   final backup appeared concurrently, it must match the supported original;
   every path cleans up only this run's temporary file.
10. Replaces the target through a same-directory temporary file, verifies the
   installed hash, and restores the backup if replacement fails.
11. Treats an already installed verified 2.4.2 DLL as an idempotent success
    only when the named backup also matches the supported original hash.
12. Restores only when the current DLL is the verified QudJP-distributed 2.4.2
    DLL and the named backup matches the supported original hash.

The README states that Steam verification, game updates, or reinstalling can
replace Harmony; users should not reapply the patch after a game update until
the Steam discussion confirms compatibility.

## Licensing

The patch ZIP includes the QudJP license, the upstream Harmony MIT license, and
third-party notices for components embedded in Harmony Fat. Repository
`NOTICE.md` distinguishes the normal mod ZIP, which does not bundle Harmony,
from the separate opt-in patch asset, which does.

## Steam Publication

The 0.5.02 Workshop changenote leads with restored Caves of Qud 1.0.5 Japanese
localization compatibility. It may mention that an optional Harmony 2.4.2
discussion will follow, but the main Workshop update does not install Harmony.

After the Workshop upload and fresh-download smoke pass:

1. Publish the draft GitHub Release.
2. Verify the Harmony ZIP through its public asset URL and checksum.
3. Create a Steam discussion titled
   `【任意導入】Harmony 2.4.2 更新パッチ（Windows / Apple Silicon Mac）`.
4. Link to the public GitHub Release and include the ZIP checksum.
5. Report the measured reduction in Windows Harmony patch application time
   from approximately 72.6 seconds to 9.4 seconds, without claiming a general
   FPS or CPU improvement.
6. Explain backup, restore, game-update, other-mod, and unsupported-version
   limitations.

## Verification

- Python tests cover deterministic package members, upstream and DLL hashes,
  checksums, and release-workflow attachment.
- Static contract tests cover explicit consent, process detection, path and
  hash allowlists, manual-only elevation, cross-session lock-file
  serialization, verified temporary backup publication, post-confirmation
  process rechecks, restorable idempotence, and restore restrictions.
- A Windows sandbox smoke uses copies of the installed game DLL in a temporary
  Caves of Qud-shaped path and proves install then restore byte identity.
- Standard QudJP release preflight, ZIP verification, Workshop upload
  preflight, fresh Workshop download comparison, and runtime log inspection
  remain mandatory.
