# Caves of Qud 1.0.5 互換対応設計

## 目的

QudJP の対象ゲームバージョンを Caves of Qud `1.0.4` から `1.0.5`
（Assembly-CSharp `2.0.211.50`）へ更新し、1.0.5 で変更された API 契約に
合わせて翻訳経路を維持する。

今回の完了条件は、1.0.5 の実ゲーム DLL を使ったビルド、L1/L2/L2G、
QudTest の patch binding、headless 翻訳検証が成功することである。Unity 上の
表示確認は自動起動せず、dev build の同期後にユーザーが行う L3 smoke として
分離する。

## 調査結果

- 更新後の public ブランチは MarketingVersion `1.0.5`、assembly version
  `2.0.211.50`、Steam build ID `24054858` である。
- 1.0.4 の基線では `just test-l1` が 5,114 件すべて成功した。
- 1.0.5 DLL を参照した `just build` は成功した。
- QudTest の全 534 patch binding は 1.0.5 でも解決できた。
- 1.0.4 と 1.0.5 の binding 差分は 10 patch type に限定された。
- `just test-l2g` は 588 件中 9 件失敗した。主要な契約変更は次のとおり。
  - `Qud.API.SavesAPI.ReadSaveJson` が `SaveGameInfo` から
    `Task<SaveGameInfo>` へ変更された。
  - `XRL.XRLGame.LoadGame` と `XRL.Core.XRLCore.SaveManagement` が
    async 化された。
  - `XRL.UI.Popup.ShowYesNo` に `Action<DialogResult>` callback が追加された。
  - 複数の async state machine 型名の連番が変わった。

## 採用方針

1.0.5 の実契約へ狭く適応する。テスト期待値だけを更新するのではなく、async
化によって処理完了前に owner scope が閉じる経路と、`Task` 自体を翻訳対象と
誤認する経路を修正する。

1.0.4 との後方互換は維持しない。対象 DLL とテストの source of truth を
1.0.5 に一本化し、実装を二重化しない。

## 変更設計

### 1. 対象バージョンの更新

現行 runtime 契約を記述する root / Assemblies / Localization の各
`AGENTS.md`、`NOTICE.md`、`README.md`、`docs/RULES.md`、
`docs/test-architecture.md`、`docs/contributing.md`、`CODERABBIT.md` にある
対象版表記を `1.0.5` に更新する。実際に `1.0.4` が記載されているファイルだけ
を変更し、新しい対象版注記を無関係な文書へ追加しない。

管理下の `steam/workshop_description.ja.txt` は対応版表記だけを `1.0.5` に
更新するが、このタスクではSteam Workshopへ公開しない。

scanner の game-version 定数と 1.0.4 由来の tracked inventory は今回変更しない。
それらは 1.0.4 snapshot の provenance を保持し、1.0.5 decompiled source を使う
tracked artifact 再生成・candidate/unresolved レビューは別タスクとする。header
の game-version だけを書き換えることは禁止する。

過去の調査・リリース報告、archive、旧 spec/plan に記録された `1.0.4` は履歴
なので変更しない。`manifest.json` の Mod version も変更しない。

QudJP の runtime build marker は 1.0.5 対応を識別できる値へ更新し、後続の
L3 smoke で対象 DLL を一意に確認できるようにする。

### 2. async セーブ情報翻訳

`SavesApiReadSaveJsonTranslationPatch` は実ゲーム戻り値と型一致する
`ref Task<SaveGameInfo> __result` を Postfix で受け取り、`ReadSaveJson` の完了
結果である `SaveGameInfo` を翻訳する。未完了の `Task` を同期 block せず、元
Task の成功、失敗、キャンセルを保った completion-aware adapter に差し替え、
成功時だけ `Size` を更新する。

adapter は元 Task の全 fault、キャンセル状態、cancellation token を呼び出し元
へ伝える。成功結果が null、翻訳辞書に一致しない、または翻訳・reflection が
失敗した場合は transform hit を記録せず、正常なゲーム Task を fault 化しない。
翻訳側の失敗は従来どおりログして元の成功結果を返す。

### 3. async owner scope

次の4 owner は wrapper method ではなく、`AsyncStateMachineAttribute` から
解決した `MoveNext` を owner target にする。

- `XRL.XRLGame.LoadGame`
- `XRL.Core.XRLCore.SaveManagement`
- `Qud.UI.MainMenu.ContinueMenu`
- `Qud.UI.SaveManagement.ContinueMenu`

scope は Task 完了まで保持せず、各 `MoveNext` invocation の Prefix で開き、
Finalizer で閉じる。await 中は scope を inactive にし、continuation が別 thread
へ移った場合も次の `MoveNext` 上で改めて開く。これにより await 中の無関係な
popup を owner traffic として誤捕捉しない。

`SingleCallsiteOwnerPopupTranslationPatch` では `MoveNext` の生成型名を owner
key にせず、target 解決時に元 wrapper の論理 key
`XRL.XRLGame|LoadGame` を対応付ける。対応表は preflight と実 patch による
複数回解決に耐える冪等な登録とし、並行 read/write を安全に扱う。nested /
reentrant owner では既存 stack に論理 key を push/pop し、内側終了後に外側
owner を復元する。

state machine のコンパイラ生成連番は直接ハードコードしない。既存の
`QudMutationsModuleWindowVariantPopupTranslationPatch` 等と同じ属性ベース解決
を使う。同期 owner は従来どおり元メソッドを target にする。Finalizer は元の
例外を変更・抑制しない。

### 4. Popup 新シグネチャ

`Popup.ShowYesNo` の新しい `Action<DialogResult>` callback 引数を exact target
解決に含める。翻訳 patch は `Message` だけを変更し、callback instance、値、
呼び出し回数、呼び出し順には触れない。将来の overload 追加で曖昧にならない
よう、name-only fallback を 1.0.5 の正常経路にしない。

`PopupShowTranslationPatch` と `TradeUiPopupTranslationPatch` の両方が新しい
overload を解決することを L2G で固定する。

### 5. state machine と動的 target inventory

async state machine の期待値は 1.0.5 DLL から属性経由で得られる実型へ更新
する。`EffectDescriptionPatch` のように派生型を動的列挙する patch は、新しい
effect 型を自動的に含む現在の動作を維持し、型名の固定リストを production
code に追加しない。

1.0.5 で `UITextSkin` が `TextBuilder` から TMP を再構築するようになったため、
active-effects title repair は binding/L2G だけでは互換性を証明できない。今回
production code を予防的に変更せず、L3 smoke の必須項目に追加する。1.0.5 で
次回 `Apply()` により修復結果が上書きされることを再現した場合は、別の failing
test と runtime 証拠を得て `SetTheText` 契約へ適応する。

## テスト戦略

実装は Red → Green → Refactor の順に行う。

1. L2 に未完了 Task の非 blocking、成功、no-op、null 成功、複数 fault、
   cancellation token、翻訳側失敗 fail-closed の failing tests を追加する。
2. L2 に4つの async ownerについて、await 後、await 中 inactive、論理 owner
   key、owner absent、nested owner 復元、例外後 cleanup の failing tests を
   追加する。
3. L2 に callback 付き `ShowYesNo` を追加し、Message だけが変わり、同一
   callback が同じ順序・同じ結果で1回呼ばれることを固定する。Harmony が直接
   patch する dummy target には Release inlining を防ぐ境界を置く。
4. L2G に Assembly-CSharp version `2.0.211.50` の identity test を追加し、
   skip 0 を必須にする。実シグネチャ期待値を更新し、9件の既知 failure を
   解消する。
5. 影響 patch を exact QudTest binding fixture に追加し、部分的 target 欠落を
   `bindings-all` だけで見逃さないようにする。
6. focused test を green にした後、L1、L2、L2G、C# 全体、build、QudTest
   exact / bindings-all、headless runtime fixtures を実行する。
7. 変更後に新識別子・新リテラルを `rg` で確認し、意図した owner/helper 以外
   に入っていないことを確認する。

## 非対象

- 1.0.4 と 1.0.5 の同時対応
- ゲーム本体の新しい localization framework への全面移行
- 全 5,430 decompiled source の翻訳 owner 再監査
- scanner の game-version 更新と tracked inventory 再生成
- 翻訳辞書・XML asset の内容変更
- ゲーム GUI の自動起動
- Harmony DLLの自動置換またはMod-private loaderの導入
- Steam Workshop への公開

## 検証ゲート

最低限、次を成功させる。

```bash
just build
just test-l1
just test-l2
just test-l2g
just test-csharp
just qudtest-headless
just qudtest-headless qudtest:bindings .artifacts/qudtest-bindings
just qudtest-headless qudtest:bindings-all /tmp/qudjp-1.0.5-bindings-all
```

自動ゲート完了時点の状態は「1.0.5 static/headless compatibility complete、
L3 pending」とする。実装後は `just deploy-dev` で 1.0.5 stable reference へ
dev-only probes を有効にしたビルドを同期する。

「1.0.5 compatibility complete」とするには、ユーザーが Rosetta launcher で
起動した後の、同期より新しい `Player.log` と対象画面で次を確認する。

- 新 build marker と patch apply/skip 数
- affected patch の target warning / skip 0
- QudJP exception、`MODWARN`、missing glyph warning 0
- Save Management の total size
- await 後の old-save / missing-save popup
- callback 付き `ShowYesNo` の代表画面
- active-effects title が次回 `Apply()` 後も日本語のまま維持されること
- 主要画面の日本語表示

翻訳辞書・XML asset は変更しないが、`Mods/QudJP/Localization/AGENTS.md` を
変更するため、repository gateに従ってrelease-note fragmentを追加する。
Workshop公開とHarmony 2.4.2再適用のSteamスレッド告知は、L3完了後のrelease
taskへ延期する。
